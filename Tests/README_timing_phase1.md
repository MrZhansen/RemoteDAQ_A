# 阶段1：时序诊断的软件边界与实测方法

本版本只补充诊断。默认GEAR0、480 Cycles，GEAR0/1周期、ADC DMA、原数字同步判据及CMD01/02/06不变。不配置测量GPIO，不启用GEAR2。本轮未连接或下载开发板。

## 1. 当前软件实际测量什么

GEAR0查看`digital_timing.gear[0]`，GEAR1查看`gear[1]`。`inactive`只用于无法归属档位的诊断，不代表支持GEAR2。原有`digital_timing`字段继续保留。

| 新记录 | 单位与范围 |
|---|---|
| `tim2_c` | 周期数：TIM2 C函数第一个DWT读取至调用采样函数返回后的DWT读取，包含采样函数内部诊断 |
| `tim2_accounting` | 周期数：上述结束点至C路径统计写入完成，**不含本条accounting统计自己的更新** |
| `dma_c` | 周期数：DMA C函数第一个DWT读取，经过HAL分发、回调及回调统计，到HAL返回后的DWT读取 |
| `dma_half_c`、`dma_full_c` | 当前IRQ实际执行半满/全满回调时，记录该次IRQ的同一C总区间 |
| `dma_accounting` | 周期数：上述DMA结束点至分类/总区间统计写入完成，不含自身统计更新 |
| `publish_half`、`publish_full` | 周期数：回调里的发布路径，含小量计数和路径标记、CH1解交织及完整快照发布；不含HAL外层分发及该条新统计更新 |
| `gpio_upper_us` | 微秒上界：两个GPIO端口读取后的CNT值加1；这是带前提的相位界限，不是精确读取时间 |

所有C区间均**不包含硬件异常进入/返回、编译器序言/尾声**。不得称为完整ISR耗时。DMA优先级1可被TIM2优先级0抢占，DWT墙钟区间包含这种抢占。

若半满与全满回调同次进入IRQ，设置`COALESCED`，两条分类记录均等于同一个IRQ总区间，不能把它们相加。发布记录分别计量各自回调。

## 2. Watch与一致性

每条记录包含`seq/valid/count/count_wraps/last/max/limit/flags/sticky_flags/over_count/anomaly_count/context`。

- `valid=1`表示记录已发布；仍须检查`flags`是否含`INVALID`，它不等于真实时序通过。
- 写入期间`seq`为奇数，最后变偶数；`DigitalTiming_Read()`单次复制校验前后序号，失败时输出不变，不重试、不关中断。
- 一致性单位是一条记录，不是整个`digital_timing`。组合C路径和accounting的最后值前，必须确认两条记录的`count/count_wraps`对应同一次IRQ；不可把两个最大值当作同次观测。
- Watch直接读多字段时也需核对前后相同偶数`seq`；不要在ISR中间暂停后把半更新字段当成完整统计。
- `count`回绕由`count_wraps`记录。其他计数及序号按32位无符号规则回绕。不能用`count!=0`代替有效性。
- DWT差值按无符号减法计算，跨一次计数回绕有效，前提是区间小于2^32周期；216MHz时约19.9秒。多次回绕、调试暂停期间的行为不作推断。
- `max`保留有效数值区间的观测最大值；异常C路径也可进入最大值。`flags/context`对应最后一条，`sticky_flags`为累计标志。

标志详见`digital_sync.h`：ERROR、EMPTY、COALESCED、INVALID、CYCLE_WRAP、OVER_BUDGET、SYNC_FAULT、LATE、PHASE_WRAP、NO_CALLBACK。

周期记录的`limit`暂取当前一个采样周期对应的CPU周期数，`over_count`只是观察告警，不会停采或替换既有保护。DMA半区真正可复用时间与`DigitalSync_HalfMatches()`检查保持原样。

## 3. 早期读取的依据与限制

原GPIO/NDTR/TIM5读取顺序及保护代码保留，新统计在原检查之后执行，不新增关键读取前的硬件访问。

TIM2名义1MHz计数。若GPIO读取前CNT=b，两个端口读取后CNT=a，且未跨更新事件，则CPU的IDR读取位于名义`[b,a+1)`微秒内。新记录的`last=a+1`是上界，`context`低16位保存b、高16位保存a。两个端口仍是依次读取，不是物理同时采样。

只有CNT顺序、量程及TIM5/NDTR同步检查正常时才记录有效上界；同步失败或回绕时标为INVALID，不将模周期相位冒充正确延迟。整周期延迟不能仅靠CNT判断，必须结合TIM5/NDTR原有校验。

480 Cycles现有阈值仍为CNT<=20，即名义经过时间小于21微秒，而不是严格小于20微秒。候选144 Cycles的独立阈值仍为CNT<=4，即小于5微秒。本轮没有配置或验证ADC144。不能直接将现有20计数阈值迁移到未来20微秒采样周期。

该界限不包含GPIO输入同步器与外部电路延迟。绝对秒值还受实际时钟误差影响。

## 4. 诊断自身开销

正常TIM2路径新增一次DWT读取，另增加三条固定大小统计发布（GPIO界限、C路径、accounting）；原关键读取前没有新计时寄存器读取。DMA外层新增三次DWT读取，并按实际半区路径写统计。每条发布包含两次屏障和固定数量RAM访问，均为O(1)，没有无界循环、格式转换或UART发送。

新增RAM为1300字节。`*_accounting`只测量主要统计尾部，自己最后一条统计更新仍未计入；不能声称已完整扣除观测开销。新的函数调用、寄存器分配、Flash等待及屏障成本必须在MCU上测量。主机脚本中的周期数都是人工输入，不是开销实测。

## 6. 后续实测操作（本轮不执行）

1. 先用本版本在GEAR0、GEAR1分别持续运行，正常UART数据和CMD01/02/06均开启；记录每档计数、最大值、告警及采样健康状态。采集窗口内不单步、不设断点、不靠高频Watch刷新制造总线负载。
2. 记录CPU实际频率和观测窗口长度，周期数除实际CPU频率换算时间。有限窗口的最大值是观测最大值，不是数学证明的WCET。正常和异常/命令负载应分开报告。
3. 需要示波器/逻辑分析仪时，另做受控测量版本：先确认PH6、PI2及PA15外接情况；保持PSC/ARR/TRGO不变，利用PA15/TIM2_CH1提供与更新周期关联的硬件参考脉冲；其相对TRGO的关系必须检查并校准。**当前固件没有该输出。**
4. 分次捕获：PH6标记TIM2 C进入/退出；另一轮PH6紧贴GPIO读取前后；DMA测量时PH6标记外层C区间、PI2标记发布区间。仪器共地、使用3.3V逻辑。参考边沿至GPIO后标记的距离仅作为包含标记写入延迟的上界；标记引入的延迟需对照反汇编和不同诊断版本评估。
5. GPIO脉宽仍排除硬件入栈/出栈与标记外的序言/尾声，不能标为完整ISR。要覆盖异常进入到返回，应另外核实可用的周期精确异常/指令跟踪设备及板上引出条件，再结合可观测事件参考。当前板载ST-LINK和现有接线没有被验证能提供该证据；SWO事件时间线也须检查时间戳精度和丢包，不能直接当作完整周期精确测量。
6. 如没有完整跟踪条件，只能交付明确边界的C区间、GPIO延迟上界及未覆盖部分，不能判定完整IRQ占用已满足未来20微秒期限。任何采样/同步错误、记录INVALID、跟踪丢失或波形关联不明，都应停止据此作通过结论。

软件逻辑测试通过与真实响应延迟/完整ISR时序通过必须分开。本轮完成诊断软件与回归，不自动进入阶段2。
