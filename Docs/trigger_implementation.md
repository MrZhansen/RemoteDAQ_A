# CMD03/04/05 触发实现说明

## 1. 命令配置闭环

控制帧由已有 `DAQ_ParseControlFrame()` 统一解析和校验：

- CMD03 参数范围 0..5，对应 OFF、CH1、CH2、D1、D2、D3。
- CMD04 参数范围 0..2，对应上升沿、下降沿、任意边沿。
- CMD05 参数范围 0..255；数字触发时仍保存并回报该值。
- 非法参数不会写入触发配置，也不会产生成功状态确认。

主程序 `UART6_DispatchControl()` 位于 `Core/Src/main.c:908`。合法命令只修改
对应字段，然后调用 `Trigger_Reset()` 丢弃旧的历史点，保证新配置不会混入旧窗口。
随后复用已有状态队列返回 12 字节状态帧。

状态帧构造仍在 `DAQ_BuildStatusFrame()` 中完成：

- Byte 5：触发源。
- Byte 6：触发方式。
- Byte 7：触发电平。
- Byte 8/9：矩形波频率。

`UART6_GetStatus()` 和 `DAQ_TransportGetStatus()` 都直接从运行变量填充这三个字段。

## 2. 同步采样来源

触发引擎不另建采样定时器。ADC3 仍由 TIM2 触发，DMA 完成半区和全区后调用
`CH1_PublishGroup()` 和 `Full_PublishGroup()`，发布一组具有同一时间索引的
CH1、CH2、D1、D2、D3 数据。

触发引擎使用 `Full_GetSnapshot()` 读取一致快照。读取前后检查快照序号和数字同步
错误，因此 CH1、CH2 与数字位不会来自不同的 ADC 采样组。

## 3. 边沿判断

`Trigger_PointValue()` 按 CMD03 选择参与比较的值：

- CH1/CH2：12 位 ADC 原始值。
- D1/D2/D3：数字快照中的 bit0/bit1/bit2。

模拟阈值由 CMD05 的 0..255 线性映射到 0..4095：

```text
threshold_raw = (level * 4095 + 127) / 255
```

`Trigger_IsEdge()` 比较相邻两个采样点：

- 上升沿：前一点不高于阈值，当前点高于阈值。
- 下降沿：前一点不低于阈值，当前点低于阈值。
- 任意边沿：满足上升或下降之一。

数字触发直接比较 0/1，不使用模拟阈值。

## 4. 环形预触发缓存

`trigger_history[24]` 保存最近 24 个完整采样点，每项同时包含 CH1、CH2 和数字位。
`trigger_history_head` 指向下一次写入位置，超过 24 点后自动回绕。

检测到边沿时，从环形缓存按时间顺序取出 24 个触发前点，再把当前边沿点放到
`trigger_frame[24]`。随后每个新采样点写入剩余位置，直到整个 `trigger_frame[50]`
完成：

```text
索引 0..23 ：触发前 24 点
索引 24    ：触发边沿点
索引 25..49：触发后 25 点
```

因此触发点在显示窗口中部；通道数组的同一索引始终属于同一采样组。

## 5. 发布和重新布防

主循环 `DAQ_TransportPoll()` 每次最多消费一个新的完整快照。未检测到边沿时不构造
数据帧，避免把不完整窗口发送给 B。窗口满 50 点后：

1. 复制到 `trigger_ready_snapshot`。
2. 调用现有 `DAQ_BuildSelectedFrameForGear()` 或 GEAR2 构建器生成 260 字节帧。
3. 通过现有 UDP 发送路径发出。
4. 清空历史缓存、边沿状态和填充计数。
5. 下一采样组自动重新布防。

触发源切回 0 后，`DAQ_TransportPoll()` 恢复原来的自由采集分支，不改变 ADC、
DMA、网络协议、帧长或 CRC。

## 6. 课程答辩要点

触发算法的核心不是“检测到边沿马上发一帧”，而是“持续保存最近 24 点；检测到边沿
后把它放在第 25 个位置，再等待 25 点填满”。这样既保留了触发前信息，又保证一帧
始终完整，并且模拟与数字通道天然时间对齐。

环形缓存只覆盖固定数组、不使用动态内存；网络发送只发生在主循环，不在 ADC DMA
中断中执行。重新布防通过清空历史并等待下一组采样完成，不需要重启 ADC 或网络。
